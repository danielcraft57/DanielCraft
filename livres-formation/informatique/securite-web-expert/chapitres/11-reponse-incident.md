# Reponse a incident

Quand (pas si) un incident arrive, la preparation fait la difference.

## Phases

1. **Preparation** : runbook, contacts, backups testes.
2. **Detection** : alertes, SIEM, logs centralises.
3. **Containment** : isoler, revoquer tokens, couper acces.
4. **Eradication** : patch, rotation secrets.
5. **Recovery** : restore, monitoring renforce.
6. **Post-mortem** : blameless, actions correctives.

## Communication

- Informer le DPO si donnees personnelles.
- Message utilisateur clair sans details techniques exploitables.

## A retenir

- Runbook ecrit avant l'incident.
- Post-mortem = amelioration continue.
