# Bravo.

Tu as fini les bases de Git et GitHub. Pas "je connais toutes les options cachees". Mais "je sais **versionner**, **brancher**, **fusionner**, **pousser**, et me sortir d'un **conflit**". C'est le coeur du metier. Chez DanielCraft, on considere que c'est ca, la vraie competence debutant solide en 2026. Pas reciter vingt flags. Piloter un depot avec methode. Tu n'es pas expert en rebase interactif. Tu n'as pas besoin de l'etre demain matin. Tu es quelqu'un qui sait allumer la machine a photos, lire status, oser une branche, joindre, pousser, arbitrer. C'est deja beaucoup. C'est surtout actionnable.

Lea repart avec des PR propres et un `.gitignore` reflexe. Max repart sans peur des conflits. Sam repart avec des ateliers rejouables en classe. Toi, tu repars avec une memoire pour ton travail - et une checklist anti-panique. Garde `mes-tests-git` ou `carnet-git`. Ce n'est pas un jouet fini. C'est un gymnase. Tu y reviendras quand tu apprendras un nouveau langage ou un nouveau framework. Git ne change pas. Tes projets, si.

## Ce que ce n'est pas

Ce bravo, ce n'est pas "tu n'auras plus jamais de message rouge". Tu en auras. La difference : tu sauras les lire. Ce n'est pas non plus "Git c'est fini, on n'en parle plus". Le muscle se perd sans pratique. Ce n'est pas un diplome officiel. C'est une competence posee. Chez DanielCraft, on prefere une competence posee a un certificat oublie. Lea le sait. Max aussi. Sam le rappelle a chaque promo.

## Ce que tu sais faire

Tu sais installer et configurer Git. Tu utilises `add`, `commit`, `log` et `status`. Tu geres branches, merge et conflits. Tu ecris un `.gitignore`. Tu manipules remote, clone, push et pull. Tu te debrouilles avec stash et les annulations raisonnables. Et tu fais des pull requests. Tu sais aussi ce que tu ne sais pas encore : rebase avance, hooks, monorepos, CI complexe. C'est sain. La carte mentale inclut les zones grises. Tu n'as pas peur d'y aller plus tard, avec prudence.

## Mission finale

Sur un vrai mini projet (meme un site de 2 pages), cree un depot GitHub. Travaille sur une branche feature. Merge via une PR. Ecris un README clair. Verifie qu'aucun secret n'est dans l'historique. Si tu codes aussi en Python, versionne ton quiz ou ton juste prix : les deux livres se parlent bien. Chez DanielCraft, on aime ces ponts entre formations. Git est le sol commun.

## La suite (quand tu voudras)

Tu pourras regarder les hooks / pre-commit, le rebase interactif (avec prudence), les monorepos, GitHub Actions (CI), et des conventions d'equipe plus fines. Mais la, respire. Une habitude posee bat dix tutos binge. Lea bingeait trop au debut. Elle a gagne plus en commitant chaque jour qu'en regardant trois heures de videos. Max aussi. Sam l'enseigne sans juger le binge - juste en proposant mieux.

## Rituel des 2 minutes

Avant chaque session :

```bash
git status
git pull
```

Apres chaque morceau utile :

```bash
git status
git add .
git commit -m "..."
git push
```

Regarde toujours `status` avant `add .`. Les habitudes battent la memoire. Colle ce rituel sur un post-it une semaine. Ensuite, c'est dans les doigts. Lea n'y pense plus. Max y pense encore le lundi. Sam le fait en demo. Toi, choisis un moment fixe : debut de session. Fin de session. Les deux, c'est encore mieux.

## Engagement de 30 jours

Chaque jour de travail : au moins un commit utile avec un message clair. Chaque semaine : une branche + une PR (meme solo). J+30 : refaire le quiz et relire ta checklist anti-stress. Tu transformeras ce livre en muscle. C'est le vrai bravo. Pas la derniere page. Les trente jours qui suivent. Chez DanielCraft, on mesure le succes au J+30 plus qu'au "j'ai fini le PDF".

## Erreur classique

Croire que "j'ai fini le livre" egal "je n'aurai plus jamais de message rouge". Non. Tu auras des messages rouges. La difference : tu sauras les lire. Autre piege : ne plus jamais committer parce que "Git c'est fini". Le muscle se perd sans pratique. Encore un piege : vouloir tout apprendre (rebase, hooks, submodules) la semaine suivante sans solidifier le sol. Monte un etage. Pas dix d'un coup.

## En vrai

Garde le dossier `mes-tests-git` ou `carnet-git`. Reviens-y quand tu apprends un nouveau langage ou un nouveau framework. Git ne change pas. Tes projets, si. Ouvre `status`. Tire. Commit. Pousse. Sens que tu pilotes. C'est ton rituel de remise en main. Si un message te bloque, relis-le jusqu'au bout avant de chercher un tutoriel : souvent la reponse est deja la. Chez DanielCraft, c'est le reflexe qui reste apres le livre.
