## Questions

1. Un Product Owner utile :
- A) Ecrit des specs de cinquante pages et disparait
- B) Porte valeur, ordre du backlog, presence
- C) Assigne les taches techniques une par une

2. Une bonne vision :
- A) Est un slogan creux interchangeable
- B) Guide pour qui / probleme / direction
- C) Liste toutes les features

3. Face aux stakeholders, le PO :
- A) Dit oui a tout
- B) Ecoute, traduit, arbitre selon la valeur
- C) Cache le backlog

4. Une user story utile a surtout :
- A) Le qui / quoi / pourquoi + criteres testables
- B) Un titre technique opaque
- C) Quarante criteres flous

5. Prioriser, c'est :
- A) Tout mettre en haute priorite
- B) Ordonner selon valeur (et risque), avec effort en tete
- C) Suivre l'ordre d'arrivee des mails

6. Discovery vs Delivery :
- A) Il faut seulement deliver sans apprendre
- B) Petits cycles d'apprentissage et de livraison
- C) Discovery sans date de decision pendant des mois

7. Une roadmap legere :
- A) Est un Gantt au jour pres engageant
- B) Montre themes/resultats revisables (ex. Now/Next/Later)
- C) Remplace le Sprint Backlog

8. Dire non clairement :
- A) Est impoli et a eviter
- B) Inclut raison + alternative + respect
- C) Se fait en silence puis sabotage

9. Avec le Scrum Master, le PO :
- A) Lui laisse la priorisation
- B) Aligne valeur et cadre en duo
- C) Le traite en secretaire

10. Avec les Developers, le PO :
- A) Ignore les alertes de taille
- B) Clarifie le quoi, respecte le comment, reste dispo
- C) Micro-manage le code

11. Une metrique de valeur :
- A) Classe les individus
- B) Lie un comportement utilisateur a une decision
- C) Compte seulement les pages vues sans action

12. Piege classique PO :
- A) Publier un top 1 clair
- B) Etre boite aux lettres ou fantome mid-sprint
- C) Timeboxer une discovery

## Corriges
